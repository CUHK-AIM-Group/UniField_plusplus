# UniField++

MRI enhancement with low-field visual planning, subject-space anatomical guidance, looped DiT refinement, and TCDecoder LoRA fine-tuning.

## Installation

Run commands from the repository root. Linux, Python 3.11, CUDA 12.8, and NVIDIA GPUs are used for training. Allocate one GPU per training worker plus a separate GPU for the Qwen planner. The per-worker batch size is **1**.

```bash
conda create -n unifield python=3.11 -y
conda activate unifield
bash scripts/install_training.sh
```

PyTorch attention evaluates the same 128-token block mask when a compatible native sparse attention extension is unavailable. To enable the optional accelerated kernel:

```bash
pip install packaging ninja
git clone https://github.com/mit-han-lab/Block-Sparse-Attention.git third_party/Block-Sparse-Attention
cd third_party/Block-Sparse-Attention
git checkout 49d6c39e4dc0303442cda3bb758b3925d4399c49
git submodule update --init --recursive
pip install . --no-build-isolation
cd ../..
```

Build the optional extension against the installed PyTorch/CUDA version; its build requires `nvcc`. Both attention implementations preserve the block connectivity. The PyTorch implementation is slower and bounds mask memory by evaluating one query block at a time. The verified package versions are recorded in `docs/tested_environment.json`.

The installation script first resolves vLLM 0.19.0's runtime dependencies, then installs the tested Transformers 5.6.0 stack for Qwen3.5. vLLM 0.19.0's published metadata declares Transformers <5, so pip reports that metadata conflict after the second step. Use the recorded versions together; a single combined resolver invocation cannot install this tested stack.

## Initialization weights

```bash
python scripts/download_weights.py
python scripts/download_weights.py --verify-only
```

`weights/manifest.json` pins every dependency by SHA-256 and records its download source. The downloader obtains FlashVSR DiT, VAE, LQ projection and TCDecoder from [FlashVSR](https://huggingface.co/JunhaoZhuang/FlashVSR), UMT5 and its tokenizer from [Wan2.1](https://huggingface.co/Wan-AI/Wan2.1-T2V-1.3B), and the planner base from [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B). Stage-1 generator LoRA and planner LoRA are distributed as initialization assets in the repository's `initialization-v1` release. AlexNet weights support LPIPS validation. Allow approximately 45 GB for installed dependencies and additional space for download caches and training outputs.

These are inputs to the released training procedure. The main model's resulting checkpoints and the fine-tuned decoder are generated by the commands below. Optimizer states, training data, and completed experimental checkpoints are not included in the initialization assets.

## Data and atlas preparation

Create `data/train.csv` and `data/val.csv`, with no header and one paired volume per line:

```text
/path/to/subject/T1w/64mT.nii.gz,/path/to/subject/T1w/3T.nii.gz
/path/to/subject/T2w/3T.nii.gz,/path/to/subject/T2w/7T.nii.gz
```

Paired low/high-field images must already correspond spatially. Keep modality and field strength in directory/file names (`T1w`, `T2w`, `FLAIR`, `64mT`, `3T`, `7T`) for task-prompt inference. Training data are supplied by the user.

Use a separate CPU registration environment:

```bash
conda create -n unifield-atlas python=3.11 -y
conda run -n unifield-atlas pip install -r requirements-registration.txt
conda run -n unifield-atlas python scripts/prepare_atlas.py \
  --list data/train.csv data/val.csv --resources weights/atlas --cache cache/atlas
export UNIFIELD_ATLAS_CACHE="$PWD/cache/atlas"
```

The registration fixed image is the native low-field MRI. MNI152NLin6Asym is registered with rigid, affine, and SyN transformations on a 2 mm working grid after intensity normalization and N4 correction. Harvard-Oxford discrete labels are propagated to the native low-field grid with `genericLabel` interpolation. Seven regional masks are constructed from explicit label sets. Details are in `docs/atlas_registration.md`.

The dataloader transforms regional masks together with the low-field image, including spacing, spatial resizing, random flips and frame sampling. Missing or geometrically inconsistent masks stop loading. No high-field image is used to estimate the atlas transformation.

## Main training

Example with two training GPUs and one planner GPU:

```bash
CUDA_VISIBLE_DEVICES=0,1,2 torchrun --standalone --nproc_per_node=2 \
  examples/WanVSR/ablation_experiments/train_plan_atlas_loop_ddp.py \
  --config configs/train.yaml --gpu 0,1,2 --vlm_device cuda:2 \
  --vlm_base_model_name "$PWD/weights/Qwen3.5-9B" \
  --train_list data/train.csv --val_list data/val.csv \
  --loop_iterations 2 --loop_block_start 10 --loop_block_end 19 \
  --num_epochs 100 --num_frames 40 --batch_size 1 --output_dir runs/main
```

`--loop_iterations` includes the first pass. The block interval is zero-based and inclusive. Plans are generated from low-field slices. Regional masks condition the mask projection, extra DiT block passes and weighted latent training loss. Default region/non-region loss weighting is 5:1. Checkpoints are written under `runs/main/phase2_*/checkpoints/`.

For a single training worker, use `--nproc_per_node=1 --gpu 0,1 --vlm_device cuda:1`. The second visible GPU still serves the planner. The planner memory fraction can be set with `WANVSR_VLLM_GPU_MEMORY_UTILIZATION`; `UNIFIELD_VLLM_MAX_MODEL_LEN` controls its context limit. `UNIFIELD_VLLM_PYTHON` optionally selects a separate vLLM Python environment. The planner uses eager execution by default; `UNIFIELD_VLLM_EAGER=0` enables vLLM compilation when supported by the environment.

## Decoder fine-tuning

Use a checkpoint produced by main training with the same loop settings:

```bash
CUDA_VISIBLE_DEVICES=0,1,2 torchrun --standalone --nproc_per_node=2 \
  examples/WanVSR/ablation_experiments/train_plan_atlas_loop_tcdecoder_lora_mri_ddp.py \
  --config configs/train.yaml --gpu 0,1,2 --vlm_device cuda:2 \
  --vlm_base_model_name "$PWD/weights/Qwen3.5-9B" \
  --train_list data/train.csv --val_list data/val.csv \
  --source_checkpoint runs/main/phase2_RUN/checkpoints/epoch_100.pth \
  --loop_iterations 2 --loop_block_start 10 --loop_block_end 19 \
  --tcdecoder_lora_rank 128 --tcdecoder_lora_alpha 128 \
  --tcdecoder_lr 5e-5 --num_epochs 100 --output_dir runs/decoder
```

The generator is frozen and only TCDecoder convolution LoRA is optimized using MRI-space L1 loss. Decoder checkpoints contain the adapter and training state; reconstruction also needs the source generator checkpoint.

## Verification

```bash
python -m unittest discover -s tests -v
```

`scripts/smoke_train.py` accepts the same training arguments plus `--smoke-stage main` or `--smoke-stage decoder`. Supply a short real pair list, prepared atlas cache and an output directory. It runs optimization, checks finite losses and parameter updates, checks cross-rank parameter agreement, saves a checkpoint and performs validation. For decoder testing, pass the checkpoint created by the main smoke run.

Smoke checks validate execution and data flow, not convergence or a paper's quantitative results. Registration provides coarse regional guidance and is not an independently validated segmentation.

The completed two-worker main/decoder smoke runs and their limits are recorded in [docs/validation.md](docs/validation.md).

For a smaller planner context during smoke tests, set `UNIFIELD_VLLM_MAX_MODEL_LEN=8192` and `UNIFIELD_VLM_MAX_NEW_TOKENS=4096` together. The context must fit both the multimodal input and the requested output budget.
